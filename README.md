# Parametric Forge

Parametric Forge owns the machine: one flake owns the macOS workstation — system defaults, GUI apps, CLI tools, fonts, overlays, secrets rails, SSH in both directions, tailnet serving, and cache policy. Consumer repos assume the machine's tools on `PATH` and never import Forge; when shell, toolchain, credential, or wrapper behavior fails in a consumer, the fix lands here. Nothing in this repo couples to a specific project — Forge aligns with consumers, never binds to them.

## [02]-[HOSTS]

`hosts/context.nix` registers `macbook` (aarch64-darwin). Its row carries identity, platform, state versions, the SSH public key, and the tailnet facts (MagicDNS domain, address ranges, server names); `flake-modules/hosts.nix` projects it into `darwinSystem` on the one perSystem nixpkgs instance (`flake-modules/nixpkgs.nix`, overlay and unfree included) and derives the flake's systems from the rows, and the home graph reads the same row.

## [03]-[DECISION_FRAMEWORK]

Rulings derive from principles, not precedent lists. These axes resolve each new situation:

| [INDEX] | [AXIS]                 | [LAW]                                                                                                          |
| :-----: | :--------------------- | :------------------------------------------------------------------------------------------------------------- |
|  [01]   | Greenfield-only        | Every touched surface rebuilds to the best current shape; no compatibility layer of any kind survives.         |
|  [02]   | One owner per axis     | One declaring file per concern; a second copy of any fact is a fork — extend the owner, never add files.       |
|  [03]   | Rows over hardcodes    | Capability lands as a parameterized row on the owning table; a new host, package, or service is one row.       |
|  [04]   | Polymorphic collapse   | Density rises inside the owning file — merged types, dispatch tables, folds — never by extraction.             |
|  [05]   | IaC over YAML          | Pulumi rows in `services/` own Forge's repo and Doppler project; each repo owns its GitHub settings and project. |
|  [06]   | Currency as review     | Newest release, prereleases included; a pin exists only for a named incompatibility and dies with it.          |
|  [07]   | No LFS                 | Repo media ships as plain git blobs kept preview-small; a project using LFS pins `git-lfs` in its `mise.toml`. |
|  [08]   | Aesthetics first-class | Visual surfaces (theme, prompt, TUI, fonts) are designed systems with single palette ownership.                |

## [04]-[DETERMINATE_NIX]

This machine runs Determinate Nix, not vanilla: Determinate owns the daemon and `/etc/nix/nix.conf` (`eval-cores`, `lazy-trees`, `experimental-features`, its caches). `modules/common/nix.nix` declares only `determinateNix.customSettings` (written to `/etc/nix/nix.custom.conf`), the flake registry, and `determinateNixd` rows; the module rejects `bash-prompt-prefix`, `external-builders`, `extra-nix-path`, `netrc-file`, `ssl-cert-file`, and `upgrade-nix-store-path-url` in custom settings. The registry pins every flake input at its locked revision, so `nix run nixpkgs#x` and `<nixpkgs>` resolve to the nixpkgs the system was built from; ids outside the inputs are spelled as full refs. Every new store path is hard-linked on arrival (`auto-optimise-store`); determinate-nixd's automatic GC frees dead paths in the background, and system and home generations stay until `nh clean all` prunes them by hand ([14]); Forge sets no `keep-outputs`, `min-free`, or `max-free`, so build-time outputs are collectable and the daemon's collector is the one policy.

## [05]-[MODULE_BOUNDARIES]

- `modules/common/` carries Nix settings and the toolchain env vocabulary: one PATH vector and one cross-surface row set, which nix-darwin's `set-environment` gives every zsh and every login or interactive bash, `launchctl config user path` and the `gui-env` agent (PATH included) replay into the GUI launchd domain, and `/etc/paths` holds for `path_helper`, so a login bash resolves Forge's tools before Apple's. A `bash -c` reads no startup file and keeps the environment of its parent. Every zsh unwinds inherited mise state with a config-free `mise hook-env`, adds the PATH entries it lacks, re-exports every managed row and unsets retired ones when the inherited `FORGE_ENV_STAMP` differs from its own (a deliberate override under an unchanged stamp survives), and sources the session cache; a `zsh -c` then applies the mise environment of its start directory from `.zshenv`, a login zsh from `.zprofile`, and an interactive zsh through `mise activate`. Rows only zsh reads stay Home Manager session variables, which bash, launchd, and GUI apps never see. The shell is Apple's `/bin/zsh` (`forge.shell`); Nix supplies its configuration, not the binary. The time zone is macOS's automatic zone, never a `TZ` row.
- `modules/darwin/` carries system-scope macOS state: defaults, security, and the Homebrew bridge. Homebrew carries GUI/proprietary bundles nixpkgs cannot ship; activation updates Homebrew, installs missing roster entries, and upgrades outdated ones (a cask without a version, such as `wezterm@nightly`, is a greedy Brewfile row, so a changed download replaces it), while cleanup stays with the manual Homebrew pass so operator installs survive. Each Mac App Store app installs through its own activation step (`mas install` under a 60 minute bound) only while `/Applications/<name>.app` is absent, so a switch never reinstalls Xcode on an empty or busy Spotlight index (the reinstall replaces the selected developer folder and `/usr/bin` shims then ask for the Command Line Tools), a hung `mas` reports and the switch moves on, and the App Store updates the apps itself. `settings/spotlight.nix` reconciles Privacy exclusions through `_MDSetExclusion` with indexing on, as System Settings does: a fixed list of cache folders plus each repository's ignored build folders under `~/Developer`. `mds` reads the length of a queued exclusion path as signed bytes and asserts on a volume path of 127 to 254 bytes (and each 256 above), so the reconcile sends no such path and lists it under `unsettable`; a failed call is listed under `failed`, retried at the next switch, and never fails activation.
- `Casks/` owns vendor GUI packages absent from Homebrew's main catalog; Homebrew taps this checkout as `bsamiee/forge` (`modules/darwin/homebrew/`), so a committed cask reaches the next activation without a push.
- Adobe applications remain Creative Cloud-owned; Typeface uses its native vendor updater. `mac-tools/default-applications.nix` owns the application rows (bundle id, handled extensions and schemes, path where a consumer opens the bundle) that the Dock, LinearMouse, and the utiluti handler reconcile read. `mac-tools/defaults/` owns user-scope macOS defaults as Home Manager `targets.darwin.defaults` rows, imported every switch: the agent hosts (WezTerm, ChatGPT with Codex, Claude, VS Code) run with App Nap off, AirPlay Receiver stays off (`currentHost` `AirplayReceiverEnabled`), so ports 5000 and 7000 stay free, and AlDente's Sleep Control keeps the Mac awake, lid closed included, until the battery reaches 20%. `home/fonts.nix` installs the curated catalog through Home Manager's native user font projection and projects its roles into fontconfig's generic families.
- `modules/home/` carries user-scope state under Home Manager: XDG hygiene, session environments, program owners. System and home scopes never mix in one module.
- `overlays/` is the admission gate for upstream packages nixpkgs lacks or pins wrongly: `manifest.nix` owns admission and recipes consume nvfetcher-generated versions and hashes. A row for a tool nixpkgs also ships is named `<attr>-current` and its consumers name it, so nixpkgs packages built against the nixpkgs attribute stay substitutable, and a row whose version nixpkgs reached goes. Admission requires a real consumer now — never anticipatory packaging.
- `services/` owns live service state as code under the TypeScript quality bar. `package.json` and `pnpm-workspace.yaml` bind the repo-root workspace without per-folder manifests. Existing service domains extend their rows; new domains get one organized owner.
- `services/` workspace commands: `node services/driver.ts preview|up|refresh [--adopt] [--refresh] [--expect-no-changes] [--target=<p>/<c>/<token>]` converges the topology; `outputs [<name>] [--reveal]` prints stack outputs. `services/driver.ts` brokers the Pulumi, Doppler, and GitHub credentials from 1Password, an ambient value of each taking its place. `mise.toml` `[env]` names Forge's Doppler project and config, so no directory scope exists.

## [06]-[SECRETS]

Doppler owns project and service configuration; 1Password owns local operator and session custody. Home Manager writes the mode-600 session cache on every activation: `op inject` runs as the 1Password service account whose token sits in `~/.local/state/op/service-account`, so a token changed in vault `Tokens` reaches the cache at the next switch with no Touch ID. The cache carries a stamp of its own content (`FORGE_OP_STAMP`): a shell that inherited another stamp drops every cached name before sourcing, names of rows since retired included (the cache exports its name list as `FORGE_OP_NAMES`), so a new zsh under an old WezTerm or Zellij holds the current values, an interactive zsh re-sources at each prompt, and a deliberate override survives while the stamp is unchanged; a process that is no shell (an agent, an MCP server) keeps what it started with. The app authorizes one read, of that service-account token, when the file is absent; after rotating that token, remove the file. `fileRows` in the same module restore credential files a tool reads from disk (GAM's `oauth2.txt`, `client_secrets.json`, `oauth2service.json`) from the store when absent, mode 600, never through the Nix store. Process-specific Doppler consumers invoke `doppler run` or `doppler secrets download` explicitly. Doppler reads its configuration through `~/.doppler`, a link to `~/.config/doppler`: the CLI prints a warning on every call that reads `DOPPLER_CONFIG_DIR` from the environment, so no surface sets it. Read names with `doppler secrets --project <p> --config <c> --only-names`; add a key in its owning config and wire its process consumer. `gh` runs on the classic all-scope token (`GH_TOKEN` reads item `GH_PROJECTS_TOKEN`), and `GITHUB_TOKEN` stays the fine-grained token for every other tool. Topology mutates only through `services/topology.ts` rows. `secrets` owns the custody law.

## [07]-[SSH]

One ed25519 key serves everything: custodied in the 1Password Personal vault, served through its agent socket, registered on GitHub for authentication and signing. No private key lands on disk: vault sync is the recovery, and a local copy shadows a dead agent. Commit signing uses SSH format and generated allowed signers. `ssh.nix` installs nixpkgs OpenSSH ahead of Apple's `/usr/bin/ssh` and projects the client config: the agent socket, post-quantum key exchange ahead of the `ecdh-sha2-nistp256` Apple's `/etc/ssh/crypto.conf` puts first, and defaults for a client no person watches (`ConnectTimeout 10`, `StrictHostKeyChecking accept-new`, and `BatchMode` on the `github.com` row). The hosts `hosts/context.nix` `tailnet.servers` names dial as `root` over Tailscale SSH and forward no agent; every host shares one connection for 10 minutes (`ControlMaster auto`, `ControlPersist 10m`) and records its host key on first contact (`StrictHostKeyChecking accept-new`, hashed). Bounded forwarding uses OpenSSH's own `-L`, `-R`, or `-D` flags instead of a resident service. rclone remotes are environment-defined and leave `rclone.conf` to the OAuth remotes rclone writes itself: each tailnet host is an SFTP remote of its own name through that `ssh`, `b2:` is Backblaze's native backend, and `r2:` is Cloudflare R2 over S3, the keys of both arriving from the session cache.

Inbound SSH is Apple's own `sshd` (Remote Login), turned on by nix-darwin (`settings/security.nix`) and limited by source address to the tailnet ranges: `AllowUsers` admits the primary user from the ranges of the host row (`ssh.plist` listens on every interface and `ListenAddress` does nothing under launchd socket activation, so a LAN or loopback connection reaches `sshd` and is refused). Authentication stays at Apple's defaults (password and keyboard-interactive included, the owner's ruling), so the address filter is the one gate: `100.64.0.0/10` is shared carrier-grade space, and a network that hands out such addresses reaches the password prompt. The one authorized key is the 1Password key (`/etc/ssh/nix_authorized_keys.d/<user>`). A remote command runs `/bin/zsh -c`, so it gets the forge PATH and the session cache. Desktop, Documents, and Downloads answer `Operation not permitted` to a remote session until System Settings > General > Sharing > Remote Login > "Allow full disk access for remote users" is on. The tailnet client is the Standalone Tailscale app (cask `tailscale-app`): `shell-tools/tailscale.nix` owns its CLI path and its start at login. `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS` names the node, so a Vite dev server accepts the tailnet host name.

## [08]-[DEPLOY_RAIL_AND_AUTOMATION]

`redeploy build|switch [nh args]` is the only sanctioned activation path: `nh darwin` builds the host toplevel with its own rom progress, prints a dix diff against the live system, and on `switch` sets the system profile and activates through the primary user's passwordless sudo. Nothing is pushed to the Cachix cache: it is public, and a switch builds the machine's own configuration; a package path goes there only through a deliberate `cachix push`.

Probe a machine that misbehaves after a switch before theorizing about it: `which -a <bin>` classifies PATH owners and cross-owner shadows, `launchctl list | rg dev.bsamiee` reconciles the declared agent set against the live table, and `readlink /run/current-system` reads the live generation against `$HOME`. Every probe is read-only, so it opens the investigation rather than closing it.

Recurring machine work is launchd-owned under the `dev.bsamiee.<name>` label grammar, each agent declared beside the surface it serves: `launchctl list | rg dev.bsamiee` is the live census of Forge agents (project tools such as Rasm's pitchfork register their own `dev.mise.*` labels outside it), `launchctl print gui/$UID/dev.bsamiee.<name>` the per-agent probe. Each new recurring job lands as one agent declaration, and `system.nix` derives a newsyslog rotation row from every agent's log path. Agents are `Background` jobs, which macOS throttles under load; an agent something waits on (`atuin-daemon`) states `ProcessType = "Interactive"`. The one scheduled agent, `menu-record`, copies the menu-choice stream `~/Library/Biome/streams/restricted/App.MenuItem/local` (SEGB segments) to `~/.local/state/menu-record` daily at 13:10 and deletes copies older than 365 days. macOS protects that folder, so `settings/system.nix` declares the job through nix-darwin with `/bin/zsh` as its program, the binary granted Full Disk Access ([13] step 8): Home Manager starts its agents through `/bin/sh`, and macOS attributes a job to its first program. Without the grant the copy fails and `~/Library/Logs/menu-record.log` holds the refusal.

`gui-setenv` (`environments/shell.nix`) publishes machine values into the GUI launchd domain and removes keys retired by each writer. Newly spawned processes inherit those values. Applications and projects own their process lifecycles, and zsh refreshes its declared machine environment before applying project configuration.

## [09]-[TOOLCHAINS]

- [PYTHON]: no machine interpreter; `uv` is machine-wide, so `uvx <tool>` runs a Python tool from any directory on an interpreter uv fetches, and a project's `mise.toml` and `uv.lock` own `python`, `ruff`, `ty`, `mypy`, and its own `uv` pin inside its tree. PyPI command-line tools the machine keeps on PATH are rows of `overlays/manifest.nix` `extensions.uv-tools` (package, extras, commands, version from an `nvfetcher.toml` `src.pypi` row, and a `python` version where the newest Python has no wheel, `afdko` on 3.13); `languages/python-tools.nix` writes one executable per command that runs `uvx [--python <version>] --from '<package>[<extras>]==<version>' <command>`. The rows are `notebooklm-py`, `trafilatura`, `pymobiledevice3`, and the font toolchain (`afdko`, `fontmake` with `pathops`, `foundrytools-cli` as `ftcli`, `glyphsLib`, `hyperglot`, `nanoemoji`, `youseedee`); each Gemini Notebook profile holds a master token, from which the library mints fresh cookies on use, so no agent refreshes them on a timer. `languages/scientific-tools.nix` installs the native command-line roster; a project owns the native libraries and headers its builds read.
- [NODE_DB]: Node, pnpm, and TypeScript are each project's `mise.toml` and `package.json` rows; npm command-line tools the machine keeps on PATH are rows of `extensions.npm-tools`, and `languages/node-tools.nix` writes one executable per command that runs `npx --package <package>@<version>` on a Nix-store Node no PATH holds (`@aredotna/cli` as `arena`, `@pnp/cli-microsoft365` as `m365` with its scripting settings in `~/.config/configstore/cli-m365-config.json`, `@tavily/cli` as `tvly`, `cf`, `ctx7`, `mcporter`). PowerShell 7 (`pwsh`) carries `ExchangeOnlineManagement`, `MicrosoftTeams`, and `PnP.PowerShell` inside its own module folder, so `Connect-ExchangeOnline`, `Connect-MicrosoftTeams`, and `Connect-PnPOnline` resolve with no gallery fetch; the session cache exports `CLIMICROSOFT365_ENTRAAPPID`, `CLIMICROSOFT365_TENANT`, and the PEM `MICROSOFT_AGENT_CERTIFICATE` that `m365` and each module sign in with app-only. The SQLite extension libraries (sqlean, spatialite, vec) sit behind the `sqlite-extended` kernel, the `duckdb` client is machine-wide beside it, and the `sqlite3` client is a project row; each `extensions.duckdb-extensions` row (`excel`, `fts`, `httpfs`, `spatial`, `sqlite_scanner`) is a pinned file linked into `~/.duckdb/extensions/v<release>/osx_arm64`, where every DuckDB client of that release finds it offline and autoload reaches it; `~/.duckdbrc` spills to `~/.cache/duckdb` (64 GiB at most), caps memory at 16 GiB, prints errors as JSON, and runs `INSTALL AND LOAD` for the rows marked `load` (`excel`, whose `COPY … (FORMAT xlsx)` never autoloads, and `spatial`, which is not autoloadable), so a release with no pinned file downloads them once instead of failing every call; a community extension (`markdown`, `pdal`) loads only after `INSTALL <name> FROM community`, since the same file linked bare fails DuckDB's signature check. PostgreSQL client tools are Home Manager-owned.
- [DOTNET_AEC]: No machine .NET SDK and no machine .NET tool; each repo's mise install owns the SDK its `global.json` pins and runs its tools through `dotnet dnx <id>`. Every SDK installs into one shared root (mise `dotnet.dotnet_root`, the root `/etc/dotnet/install_location_arm64` names), so a process that captured `DOTNET_ROOT` or the root's PATH segment reaches each SDK a later `global.json` names. That `dotnet` reaches PATH through the mise shim segment of the one PATH vector every session and launchd surface projects, so a login shell, a launchd agent, and a GUI app resolve the pinned SDK without the interactive `mise activate` hook.
- [MISE]: global settings keep project tools reachable from every directory: `auto_install`, on by default, keeps the shim directory on PATH: behind the Nix and Homebrew folders on the PATH vector bash, launchd, and GUI apps read, and first in zsh, where `mise hook-env` (`activate_shims`) puts it ahead of the vector and behind a project's own tool directories; a shim runs the version a config in reach selects, else the same command from the rest of PATH (a command Forge installs runs the Forge build), else, through `shims.fallback_to_installed`, the newest installed version, and `ignored_config_paths` stops a `mise.toml` under `/private/tmp` or `/private/var/folders` from steering a shell. A tool that a project installed therefore runs from `~`, from a scratch directory, and after `cd <project>` inside one command. `energyplus` and `openstudio` are Forge-owned machine runtimes with disjoint ambient identities.
- [FONTS]: `media-tools/default.nix` holds the Perso-Arabic font toolchain: `harfbuzz-current` with the raster, Cairo, vector, GPU, and ICU features (`hb-shape`, `hb-view`, `hb-raster`, `hb-vector`, `hb-subset`), release binaries `fontc`, `fontspector`, `shaperglot`, `diffenator3` and `diff3proof`, `fontheight` built from its crate, nixpkgs `fribidi`, `ots-sanitize`, `ttfautohint`, and `gftools`, `fontforge-current` (the 20251009 release with upstream's two `importlib.metadata` plugin-discovery commits, since its `pkg_resources` import fails on current setuptools), and the uv rows above. `pango-view` (`languages/scientific-tools.nix`) runs with `PANGOCAIRO_BACKEND=fc` unless a caller sets it, so a `FONTCONFIG_FILE` naming a folder decides which font renders; `hb-view` shapes one direction per line, so mixed Persian and Latin lines go through `pango-view`.

## [10]-[TERMINAL_MESH_AND_THEME]

`modules/home/theme.nix` owns the palette and serializes it into every visual consumer. `modules/home/programs/apps/chords.nix` owns the chord vocabulary and projects each row into Karabiner, Zellij, WezTerm, and hint content. The mesh is two layers: every WezTerm window attaches the Zellij session named by its workspace, and each pane is a shell. Zellij tracks what each pane's agent reports (working, needs you, done, failed): Hyper `i` opens the inbox, Hyper `n` jumps to the next pane that needs the owner in any session, session, tab, and pane modes hold the mute, watch, and session-history keys, and the top bar shows the count across sessions (`◉ 1 need you · 2 running`) and a marker per tab in the `inbox` palette roles. Both bars are one forge plugin, `zellij/statusbar/` (Rust, built for `wasm32-wasip1` by `pkgsCross`, MIT with zjstatus's notice, from which its format syntax comes): it reads the counts Zellij pushes (`GlobalAttentionUpdate`), redraws only when a line changes, and starts no process; a click on a tab switches to it, on the swap layout name cycles it, on the count opens the inbox. atuin records each command (text, directory, exit status, duration) and every agent thread through the `dev.bsamiee.atuin-daemon` agent; its pty proxy stays off, because a proxy between Zellij and the shell hides the pane's running command and directory from Zellij. Zellij sets each new pane's PATH, TERM, and COLORTERM (`env` block), so a pane of a long-lived or launchd-born server never inherits them from the server's start. zsh emits OSC 133 prompt and command marks with the command text and OSC 7 directory reports itself, so the inbox lists finished and failed commands and new panes open in the pane's folder. Agent panes resurrect through Zellij's own `set-resurrect-command`: a hook of each harness runs `zellij-agent-resume <harness>` (Claude Code and Codex on `SessionStart`, which also fires on `/clear`, compaction, and resume; Antigravity on `PreInvocation`, since its `SessionStart` skips resumed conversations), which declares `claude --resume <id>`, `codex resume --no-daemon <id>`, or `agy --remote-control --conversation=<id>` for its pane inside an interactive `/bin/zsh` and saves the session at once. A print or `exec` run declares nothing. A Claude exit from the prompt (`prompt_input_exit`) and a Codex `SessionEnd` clear the declaration only while it still names that session; an Antigravity pane keeps its last conversation until the pane closes. Every other running program comes back as a shell (`post_command_discovery_hook` prints the shell). Codex sessions attached to its app-server daemon run hooks in the daemon, which owns no pane, so only `--no-daemon` Codex sessions resurrect. A private `tmux -L <name>` server, configured by `programs.tmux`, is the fixed-size headless terminal an agent drives a TUI in; it drops the Zellij pane variables so nothing inside it declares for the outer pane. The editor is Visual Studio Code, outside the mesh: `EDITOR` and `VISUAL` name one script on every surface, `code-wait`, which runs `code --wait`, a delta file link is a `vscode://file/<path>:<line>` URL that VS Code's own handler opens from any terminal, and a WezTerm quick-select `file:line` span runs `code --goto` on it.

## [13]-[FRESH_MACHINE_BOOTSTRAP]

Everything lands declaratively with the first switch; only these steps are manual, each with its proof:

1. Install Determinate Nix via the macOS package — the `curl | sh` installer can die creating the encrypted APFS volume and strand fstab/synthetic.conf residue.
    - Command: `curl -sSfL https://install.determinate.systems/determinate-pkg/stable/Universal -o determinate.pkg && sudo installer -pkg determinate.pkg -target /`
    - Verify: `nix --version` reports Determinate
2. Install the Xcode Command Line Tools and Homebrew via its macOS package — activation's `brew bundle` requires `brew`, the tap and clone below need `git`, and Homebrew's own `brew update` keeps it on the newest stable tag from then on.
    - Command: `xcode-select --install`, then `curl -sSfL https://github.com/Homebrew/brew/releases/latest/download/Homebrew.pkg -o Homebrew.pkg && sudo installer -pkg Homebrew.pkg -target /`
    - Verify: `/opt/homebrew/bin/brew --version` reports the latest release
3. Sign into the 1Password app; enable Settings → Developer → SSH agent + CLI integration. GUI-only by vendor design; key custody syncs from the cloud — zero key handling.

## [14]-[MAINTENANCE]

- Format: `nix fmt -- --ci` — full proof: `nix flake check`.
- Inputs, in one pass on a clean tree: `sudo determinate-nixd upgrade`, then `nix flake update` and `nix shell .#nvfetcher-current -c nvfetcher -o overlays/_sources -k =(printf '[keys]\ngithub = "%s"\n' "$(gh auth token)")` together (zsh `=()` hands nvchecker a keyfile every check reads), prune each overlay row nixpkgs caught up to and advance the rest (after a failed build, `determinate-nixd fix hashes --auto-apply` rewrites the dependency hash nvfetcher cannot compute, `ctypesgenHash`), `biome migrate --write` after a biome bump, one `redeploy switch`, the Homebrew pass, then `nh clean all --keep 1`.

Every family moves through the ordered update sequence on demand; Homebrew currency runs `brew update && brew upgrade && brew cleanup`.
